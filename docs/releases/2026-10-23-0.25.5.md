# 0.25.5 — Copying a wrapped command keeps its spaces

Release scope: everything, in the one release `v0.25.5`: the Hub, node and CLI,
the desktop app for macOS, Windows and Linux, the Android app, and iOS through
TestFlight, all from 0.25.4. The fix is interface-only and also reaches 0.25.4
apps through the `stable` Web UI channel.

## Changes

- **Copying a wrapped command keeps its spaces in select mode** (#597). On a
  phone or tablet, Select → Copy of a long command that Claude Code wrapped
  could drop the space before a long path and add one inside it
  (`-f/private/…07c bc2a…`). When a row fills up exactly, Claude Code moves
  the space before the next word to the start of the next row and doesn't
  draw it; the copy now accounts for that. A row that the terminal
  soft-wraps also keeps its trailing spaces.

## Validation and publication

- Run CI on the release preparation, then merge and tag `v0.25.5` on the merge
  commit. The Release workflow checks the tag against both versions, builds
  every component into the draft, and publishes it once every asset and
  `latest.json` are in place.
- Check that `updater-channel` and `mirror` uploaded, not skipped.
- After publishing:
  - `https://offdesk.dev/updates/desktop/latest.json` and GitHub's
    `desktop-latest/latest.json` name 0.25.5, and a desktop app on 0.25.4
    offers the update.
  - `curl -fsSL https://offdesk.dev/install | sh` installs 0.25.5.
  - On a phone or tablet, have Claude print a command with a long path that
    wraps, then Select → Copy it: it pastes as the original single line.
  - Offer the iOS build to testers with `TestFlight Release Distribution`,
    `release_tag` `v0.25.5`.
- Publish the same Web UI to the `stable` channel.
