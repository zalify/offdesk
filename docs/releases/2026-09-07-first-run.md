# First-install release — September 2026

Release authorized after the DMG installation-layout fix. This document records
release scope and gates; publishing state is verified against release artifacts.

| Component | Current | Release | Tag |
| --- | --- | --- | --- |
| Hub / CLI / node | 0.20.3 | 0.20.4 | `v0.20.4` |
| Desktop (macOS, Windows, Linux) | 0.6.3 | 0.6.4 | `desktop-v0.6.4` |
| Android | 0.6.5 | 0.6.6 | `app-v0.6.6` |
| iOS / TestFlight | 0.6.5 | 0.6.6 | `ios-v0.6.6` |

All tags must resolve to the same merged release-preparation commit. Keep #144
and #406 excluded. Cloud infrastructure and billing/service implementation stay
in their private repository; this release does not reclassify the Cloud beta.

## Changes since the previous stable packages

- Automatically recover incomplete local Hub setup and verify the Hub, local
  machine registration, live node connection and tmux before presenting phone
  pairing as ready. New desktop users do not need to run the installer script.
- Show an appropriate waiting state when a phone connects before a machine is
  ready, and retain saved connections in the reconnect flow during startup.
- Handle macOS Chinese punctuation through the Apple input path.
- Improve Android system-navigation/cutout insets and scan lifecycle handling.
  Do not claim that all reported camera/black-screen cases are resolved (#448).
- Give macOS DMGs a fixed installation window, real left-to-right drag targets
  and instructions. Preserve layout in release CI and verify the image metadata.
- Add illustrated English/Chinese Mac setup documentation. Website-only CI now
  runs the site checks without compiling unrelated native apps.

## Validation and distribution

- Native Mac Mini RC.1 accepted automatic setup in a clean standard user account,
  terminal I/O, app quit/reopen and test-Hub restart. Physical phone pairing and
  a complete logout/login cycle in that account were not part of that acceptance.
- RC.3 app compiled on Mac Mini; final DMG packaging used the headless RC helper.
  Image integrity, strict contained-app signature, version and Finder geometry
  passed. The old unstyled RC.2 was rejected by the new artifact guard. Visual
  Finder inspection remains pending while the user's display is off.
- RC signatures are ad hoc. Verify Developer ID/notarization separately on the
  final universal Mac app. Check both architectures and bundled Hub/node versions.
- Android signed release CI must pass startup/input smoke before assets are
  published. Keep the production application ID and signing key; compare the
  certificate against 0.6.5 and record any limits to native upgrade validation.
- iOS uses a new numeric build number. Upload to TestFlight, preserve the existing
  encryption declaration and no-France selection, and use the existing testers
  group. Apple review/processing is distinct from successful IPA upload.
- Stage GitHub releases as drafts until artifact checks pass. Publishing desktop
  promotes `desktop-latest/latest.json`; verify that channel after promotion.
- Publish the complete Hub binary set, keep GitHub global Latest on the Hub tag,
  and check the official installer selects 0.20.4. Do not restart live user
  services merely to verify a downloadable binary.
- After publishing, update the homepage, README and setup-guide version note,
  then verify `/mac`, `/windows`, `/linux`, `/apk`, `/desktop` and TestFlight.

Known first-run issue: “Open my terminal” may show an empty Watching screen.
Taking control reveals Start terminal. The guide documents that step; this
release does not claim that empty-terminal interaction has been redesigned.
