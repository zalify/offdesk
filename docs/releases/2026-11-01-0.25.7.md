# 0.25.7 — Android IME keeps the first characters after Enter

Release scope: everything, in the one release `v0.25.7`: the Hub, node and CLI,
the desktop app for macOS, Windows and Linux, the Android app, and iOS through
TestFlight, all from 0.25.6. The fix is interface-only and also reaches 0.25.6
apps through the `stable` Web UI channel.

## Changes

- **Android IME no longer drops the first characters after Enter** (#607). With
  a Chinese IME on Android, the first commit after Enter could lose its
  beginning: after `你好` + Enter, typing `你好世界` sent only `世界`. The input
  patch that stops IME commits from being sent twice (#301) kept counting text
  that xterm had already cleared from its input field (on Enter, Ctrl+C, blur
  and paste); it now stops at what the field still holds. A new e2e spec runs
  as an Android phone, which the IME tests didn't cover before.

## Validation and publication

- Run CI on the release preparation, then merge and tag `v0.25.7` on the merge
  commit. The Release workflow checks the tag against both versions, builds
  every component into the draft, and publishes it once every asset and
  `latest.json` are in place.
- Check that `updater-channel` and `mirror` uploaded, not skipped.
- After publishing:
  - `https://offdesk.dev/updates/desktop/latest.json` and GitHub's
    `desktop-latest/latest.json` name 0.25.7, and a desktop app on 0.25.6
    offers the update.
  - `curl -fsSL https://offdesk.dev/install | sh` installs 0.25.7.
  - On Android with a Chinese IME, type a line, press Enter, then type
    another: it arrives whole.
  - Offer the iOS build to testers with `TestFlight Release Distribution`,
    `release_tag` `v0.25.7`.
- Publish the same Web UI to the `stable` channel.
