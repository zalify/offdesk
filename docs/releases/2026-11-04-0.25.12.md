# 0.25.12 — Files of any size into a terminal

Release scope: everything, in the one release `v0.25.12`: the Hub, node and CLI,
the desktop app for macOS, Windows and Linux, the Android app, and iOS through
TestFlight, all from 0.25.11. Chunked uploads touch the Hub, the node and the
interface; the revived-terminal fix is Hub only.

## Changes

- **Files of any size into a terminal, with progress** (#623). The attach
  button and drag-drop used to send the whole file as one Base64 message, so
  the 32 MiB message limit on the Hub, the node and the encrypted transport
  capped a file at 23 MiB, with no progress. Files now go over the same
  terminal connection in 1 MiB chunks; the node writes each chunk and
  acknowledges it before the next is sent, so the progress shown is bytes on
  the node's disk and the Hub never holds a whole file. There is no fixed
  size cap; free space on the node is the limit. The saved path is pasted
  into the terminal without Enter, as before.
  - The attachment review on the phone shows a percentage and a bar for the
    file being sent; a desktop drop shows a strip above the terminal.
  - Nodes advertise `upload-chunked-v1`. With an older Hub or node the
    interface falls back to the single-message upload for files up to 23 MiB
    and says the Hub and node need an update above that.
  - Clipboard image paste is unchanged.
- **Terminals a restarted node reports are revived** (#622). When a node
  reconnected and reported a terminal whose Hub row had been marked destroyed,
  the Hub treated it as new: the row stayed destroyed and its title was
  overwritten with the node's empty one, so title and folder updates were
  dropped from then on. The row is revived and the stored title kept when the
  node reports none.

## Upgrading

- Uploads over 23 MiB need the new Hub, the new node on the target machine
  and the new interface (built into the Hub for browsers, bundled in the
  desktop and mobile apps). Any older piece falls back to the 23 MiB path.
- Partial uploads live in a private `offdesk-upload-*` directory under the
  node's temp dir and are removed on abort, on the terminal closing, and after
  two minutes without data.
- The revived-terminal fix needs only the new Hub. No schema change.

## Validation and publication

- Run CI on the release preparation, then merge and tag `v0.25.12` on the merge
  commit. The Release workflow checks the tag against both versions, builds
  every component into the draft, and publishes it once every asset and
  `latest.json` are in place.
- Check that `updater-channel` and `mirror` uploaded, not skipped.
- After publishing:
  - `https://offdesk.dev/updates/desktop/latest.json` and GitHub's
    `desktop-latest/latest.json` name 0.25.12, and a desktop app on 0.25.11
    offers the update.
  - `curl -fsSL https://offdesk.dev/install | sh` installs 0.25.12.
  - Drop a file over 23 MiB onto a terminal on a machine with the new node:
    the strip shows progress, the quoted path lands in the terminal, and the
    file's hash matches on the machine.
  - Offer the iOS build to testers with `TestFlight Release Distribution`,
    `release_tag` `v0.25.12`.
