# v0.33.3

A node and CLI release for the agent browser. The app shells are rebuilt with the same version and no interface change.

## What changed

- **`offdesk browser upload --nth N`** (#702): fills the Nth `input[type=file]` of the page directly, for pages whose file inputs and upload triggers have no snapshot ref. Without a ref or `--nth`, a page with several file inputs now answers with a numbered list that says which input is which (the text of the form item around each).

Already in v0.33.2, but missing from its note:

- **`offdesk browser click --text` skips covered elements** (#695, issue #694): among matches of the same exactness it prefers one that no other element covers, so a cell hidden behind a drawer no longer wins over the visible option.
- **`offdesk browser click --xy X,Y`** (#695): clicks a viewport point in CSS pixels (1:1 with a plain screenshot).
- **`snapshot` shows number-input / spinbutton values** (#695).
- **`offdesk vault set NAME`** (#701): on a terminal it prompts and hides the input instead of waiting silently; piped stdin is unchanged.

## Updating

- `upload --nth` and `click --xy` need all three at this version or later: the Hub, the node (`offdesk-node`, on the machine that runs the browser) and the CLI (`offdesk`, where the agent runs). The Hub parses each browser command before forwarding it, so an older Hub drops the new `nth` / `xy` fields: `upload --nth` then answers with the numbered list instead of filling, and `click --xy` with "click needs exactly one of ref, text or xy". Update the Hub first.
- The covered-element check of `click --text`, the numbered list of file inputs and spinbutton values need only the node.
- `vault set` needs only the CLI.

## Check after publishing

- `offdesk browser upload --help` lists `--nth`; `offdesk browser click --help` lists `--xy`.
- On a page with two file inputs, `offdesk browser upload <browser> --file F` prints the numbered list, and `--nth 2` fills the second.
