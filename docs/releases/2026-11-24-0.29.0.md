# 0.29.0: Zero-copy binary IPC, adaptive local echo, and client-only Hub

Release scope: everything ships in the one release `v0.29.0`, upgrading from
0.28.3:

- the Hub, node and CLI;
- the desktop app for macOS, Windows and Linux;
- the Android app;
- iOS, through TestFlight.

The Hub, node, encrypted client, desktop/mobile native shell, and bundled UI all
changed.

## Changes

- **Zero-copy Tauri binary IPC, fast deflate, and adaptive local echo prediction** (#663).
  - **Zero-Base64 Tauri binary IPC**: `secure_ws_send` and `secure_http` /
    `secure_ws_recv` now pass raw binary payloads (`InvokeResponseBody::Raw` /
    `ArrayBuffer`) across the Tauri bridge without Base64 encoding overhead or
    extra GC pressure.
  - **Faster terminal stream compression**: lowered `deflate-raw-v1` compression
    level from 6 to 3 to cut per-frame CPU latency during high-throughput output.
  - **Mosh-style adaptive local echo prediction**: displays printable
    keystrokes immediately as a cursor overlay when observed echo RTT is
    ≥ 35ms, reconciling automatically as server output arrives.
- **Client-only Hub and Web Preview removal** (#664).
  - **Client-only production Hub**: removed the embedded web UI (`embed-ui`,
    `rust-embed`) and stripped the Node/Expo build stage from the production
    Docker image. Production `offdesk-hub` now serves API/WebSocket/Noise
    traffic only unless `--static-dir` / `OFFDESK_STATIC_DIR` is explicitly set;
    desktop and mobile clients continue bundling the UI locally.
  - **Removed Web Preview**: deleted `offdesk-preview-transport`, Hub web
    preview proxy routes, machine preview streaming, `WebPreviewDialog`, and
    preview-edge E2E fixtures.

## Upgrading

- Update the Hub, node and CLI (`curl -fsSL https://offdesk.dev/install | sh` or
  the Hub container image), and update desktop/mobile apps to pick up the
  binary IPC, fast deflate, and local echo prediction improvements.
- If your deployment previously set `OFFDESK_PREVIEW_DOMAIN` or routed a
  wildcard preview domain to the Hub, those settings are no longer used and can
  be removed.

## Validation and publication

- Run CI on the release preparation, then merge and tag `v0.29.0` on the
  merge commit. The Release workflow checks the tag, builds every component
  into the draft, and publishes the release once every asset and
  `latest.json` are in place.
- Check that `updater-channel` and `mirror` uploaded rather than skipped.
- After publishing:
  - Check that `https://offdesk.dev/updates/desktop/latest.json` and GitHub's
    `desktop-latest/latest.json` name 0.29.0.
  - Offer the iOS build to testers with `TestFlight Release Distribution`
    (`release_tag` `v0.29.0`).
