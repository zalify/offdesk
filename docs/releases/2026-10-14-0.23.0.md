# 0.23.0 — one release for everything, and update prompts

Release scope: everything, in the one release `v0.23.0`: the Hub, node and CLI
(from 0.22.0), the desktop app for macOS, Windows and Linux and the Android app
(from 0.9.0), and iOS through TestFlight (from 0.9.2). It is the first release
made the way [Releasing](../releasing.md) describes: one tag, every component
at the same version, built from the same commit.

## Changes

- **One release per version.** `v0.23.0` holds the Hub, node and CLI
  binaries, the desktop installers and updater files, the Android APKs and the
  iOS `.ipa`, and is GitHub's Latest release. There are no separate
  `desktop-v*` or `ios-v*` releases any more; `desktop-latest` still points
  installed desktop apps at the newest desktop build. Android apps up to 0.9.x
  find this update through a copy of the APKs released as `app-v0.23.0`. The
  app versions jump from 0.9.x to 0.23.0 to join the Hub's numbering.
- **Update prompts** (#531–#534). Nodes report their version, and the Hub
  serves its own version, the newest release and each node's version
  (`GET /api/version`, `GET /api/machines/versions`).
  - CLI: `offdesk version`, a print-only `offdesk update` listing what is
    behind, a NODE column in `offdesk machines`, and at most one notice a day
    when the CLI or Hub is behind.
  - Phone: a notice when a scanned Hub is older than the app, an app update
    card above the key bar (Android installs it; iPhone opens TestFlight), and
    node versions in the Machines sheet.
  - Desktop: an update card above the status line, Settings › versions, the
    phone panel on a node machine pointing to the Hub, and a restart-to-update
    item in the menu bar. On the Hub machine the app restarts the bundled Hub,
    node and Cloud connector services when their version changes.
- **Themes** (#535): Graphite, a softer dark, is the default; Midnight keeps
  the 0.9.0 look; Slate, Ember, Paper, Sepia and Sage join them, and the
  terminal follows the theme. Apps already on the stable Web UI have them;
  this release builds them in.
- **Web UI updates on every app** (#536): Windows and Linux take interface
  updates like macOS and Android, and so does iOS, whose build carries the
  Web UI release key and is refused without it (#538).
- After the Offdesk DEV rename, a hub Mac's Cloud connector and nodes whose
  `PATH` led into the old app bundle are repaired too (#530).

## Validation and publication

- Merge #539 first, so the Android updater, the iPhone update notice and
  offdesk.dev's download links read `vX.Y.Z` releases.
- Run CI on the release preparation, then merge and tag `v0.23.0` on the merge
  commit. The Release workflow checks that the tag matches both versions,
  builds every component into the draft, and publishes it once every asset
  and `latest.json` are in place.
- After publishing:
  - `desktop-latest/latest.json` names 0.23.0 with links under
    `releases/download/v0.23.0/`, and a desktop app on 0.9.0 offers the
    update.
  - `app-v0.23.0` holds the same three APKs, is not Latest, and an Android app
    on 0.9.0 offers 0.23.0.
  - `curl -fsSL https://offdesk.dev/install | sh` installs 0.23.0, and
    `offdesk version` reports it.
  - The iOS build reached TestFlight; offer it to testers with `TestFlight
    Release Distribution`, `release_tag` `v0.23.0`.
- Publish the same Web UI to the `stable` channel.
