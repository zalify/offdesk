# Desktop, Android and iOS 0.8.0, Hub 0.22.0 — Offdesk DEV, and terminals an agent opened

Release scope: desktop macOS, Windows, and Linux (`desktop-v0.8.0`), Android
(`app-v0.8.0`), iOS through TestFlight (`ios-v0.8.0`), and the Hub, node and
CLI (`v0.22.0`).

## Changes

- The installed app is now called **Offdesk DEV** (#517). Settings, saved
  hubs, Keychain entries and pairing stay where they are; the `offdesk` CLI,
  `offdesk-hub` and `offdesk-node` keep their names. How each platform moves
  to the new name is in
  [The app is now called Offdesk DEV](2026-10-13-offdesk-dev-name.md).
- Terminals an agent opened say so (#518). When a terminal is opened with an
  API token, as `offdesk open` does, the Hub records it. The apps show an
  **agent** marker on its tab, under the terminal's name on the phone, in the
  phone's session switcher and in the Workspace Manager, and
  `offdesk ls` has an `OPENED BY` column (`--json` includes `opened_by`). The
  label is the API token's name, or `offdesk open --label <name>`. Terminals
  opened from an app are not marked.

The marker needs Hub 0.22.0, which the desktop app brings on a hub Mac or Linux
machine. Older apps ignore it; an older Hub marks nothing.

## Validation and publication

- Run CI on the release preparation, then merge and tag `desktop-v0.8.0`,
  `app-v0.8.0`, `ios-v0.8.0`, and `v0.22.0` on the merge commit.
- Verify the desktop draft as for 0.7.8, plus the rename:
  - macOS: update a Mac running `Offdesk.app` 0.7.11 that is a hub. After
    the update it opens as `Offdesk DEV.app`, `Offdesk.app` is gone, and the
    hub and node services run from the renamed app and reconnect.
  - Windows: installing over 0.7.11 leaves one "Offdesk DEV" entry in Apps &
    features and no old Start menu shortcut.
  - Linux: the `offdesk-dev` `.deb` installs over `offdesk`.
- Publish the desktop release without moving GitHub's global Latest off the
  Hub release, and check the `desktop-latest` manifest.
- Publish `v0.22.0` as the Latest release and check that the install script
  picks it up.
- Verify the Android release APK is signed and starts, and that the iOS build
  reached TestFlight.
- Publish the same Web UI to the `stable` channel.
