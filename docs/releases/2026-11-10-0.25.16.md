# 0.25.16: Typing in the agent browser can't get stuck

Release scope: everything ships in the one release `v0.25.16`, upgrading from
0.25.15:

- the Hub, node and CLI;
- the desktop app for macOS, Windows and Linux;
- the Android app;
- iOS, through TestFlight.

The fix is in the interface and the node.

## Changes

- **Typing in the agent browser can't freeze** (#635, OFF-120). Taking over the
  agent browser and typing an email address stopped responding at "@". The
  freeze wasn't reproduced, so this closes the two ways one key could stop
  every key after it:
  - **Interface:** the viewer drops keys while it believes an input-method
    composition is open. If the composition ended without the browser saying
    so, that state never cleared, and every later key was dropped. It now
    clears on any key the browser doesn't mark as composing, and on blur.
  - **Node:** keys go to Chrome one at a time. A key Chrome never acknowledged
    held up every key after it for 30 seconds each. Each key now waits at most
    2 seconds. A key that times out is logged ("agent browser input … not
    acknowledged"), so a repeat of the freeze leaves evidence in the node's
    log.

## Upgrading

- The interface part reaches installed apps through the Web UI `stable`
  channel. The node part needs the new node on each machine.

## Validation and publication

- Run CI on the release preparation, then merge and tag `v0.25.16` on the
  merge commit. The Release workflow:
  - checks the tag against both version numbers;
  - builds every component into the draft;
  - publishes the release once every asset and `latest.json` are in place.
- Check that `updater-channel` and `mirror` uploaded rather than skipped.
- After publishing:
  - Check that `https://offdesk.dev/updates/desktop/latest.json` and GitHub's
    `desktop-latest/latest.json` name 0.25.16.
  - Take over the agent browser on a sign-in page and type an email address
    with "@": every character arrives.
  - Offer the iOS build to testers with `TestFlight Release Distribution`
    (`release_tag` `v0.25.16`), and publish the Web UI to `stable`.
