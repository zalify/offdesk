# 0.28.1: folders given in full match ones allowed with ~

Release scope: everything ships in the one release `v0.28.1`, upgrading from
0.28.0:

- the Hub, node and CLI;
- the desktop app for macOS, Windows and Linux;
- the Android app;
- iOS, through TestFlight.

Only the Hub changed. The node, the CLI and the apps are rebuilt at the new
version with no other changes.

## Changes

- **A folder given in full matches one allowed with `~`** (#657, OFF-143).
  A bridge or token allowed to start agents in `~/workspaces/Zalify` refused a
  start in `/Users/<me>/workspaces/Zalify` ("That folder isn't one this token
  may start in"), because the Hub compared the folders as text. offdesk.so's
  AI teammates keep folders in full, so handing a task to one failed. The Hub
  now reads `~` as the machine's home on both sides; with no home known it
  compares text as before. The node's real-path check is unchanged.

## Upgrading

- Update the Hub on each machine (the desktop app updates its bundled one).

## Validation and publication

- Run CI on the release preparation, then merge and tag `v0.28.1` on the
  merge commit. The Release workflow checks the tag, builds every component
  into the draft, and publishes the release once every asset and
  `latest.json` are in place.
- Check that `updater-channel` and `mirror` uploaded rather than skipped.
- After publishing:
  - Check that `https://offdesk.dev/updates/desktop/latest.json` and GitHub's
    `desktop-latest/latest.json` name 0.28.1.
  - With a bridge allowed `~/…`, hand a task to an AI teammate whose folder is
    the same folder in full, and check it starts.
  - Offer the iOS build to testers with `TestFlight Release Distribution`
    (`release_tag` `v0.28.1`).
