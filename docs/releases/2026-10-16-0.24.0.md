# 0.24.0 — agent runs: see, answer and start coding agents from anywhere

Release scope: everything, in the one release `v0.24.0`: the Hub, node and CLI,
the desktop app for macOS, Windows and Linux, the Android app, and iOS through
TestFlight, all from 0.23.0.

## Changes

- **Agent runs** (#542, #543). The Hub knows which coding agent (Claude Code,
  Codex) runs in each terminal and keeps a run for it: working, waiting on you,
  idle, done. Claude Code's hooks say what it's doing and what it asks, and
  agents report their own work with `offdesk run note|blocked|done`.
  `offdesk agents hooks install` sets the hooks up, and for Codex chains
  Offdesk's `notify` in front of your own (#553).
- **Answer from anywhere** (#544, #552). Approve, decline, pick an option or
  answer in words from the phone's attention strip or `offdesk answer`; Offdesk
  types it into the terminal. Checked in real Claude Code and Codex sessions:
  questions stay questions, and a decline ends the wait.
- **Claude Code's folder trust prompt** (#554). An agent in a folder Claude Code
  hasn't opened waits on you with a trust approval instead of looking busy. Yes
  highlights "Yes, I trust this folder" before Enter (the menu has no numbers
  and wraps); no exits Claude Code. Answering it needs this node version
  (`agent-choose-v1`).
- **Start agents** (#545). `offdesk start` opens Claude Code or Codex in a new
  terminal with its first message, a permission mode and your own reference.
- **Scoped API tokens** (#546). A token can be limited to agent runs (read,
  answer, approve, start), to some machines, agents and folders, and to a
  content level; it never reaches terminals. `offdesk tokens` (#548).
- **Webhooks** (#547). Agent run events, signed with Standard Webhooks and
  retried, to your URL; ntfy example. `offdesk webhooks` (#548).
- **Agent bridge** (#549, #551). The Hub keeps a connection to a server you pair
  with a one-time code (`offdesk bridges add`), which sees runs and, within what
  you allow, answers them and starts agents. Offdesk Cloud is one such server.
  MCP tools for agent runs, and Settings › Bridges and token activity.
- Fixes: macOS disk stats read with `statfs` (#550); the app offers only fonts
  the device can draw, with three more terminal fonts (#541).

## Validation and publication

- Run CI on the release preparation, then merge and tag `v0.24.0` on the merge
  commit. The Release workflow checks that the tag matches both versions,
  builds every component into the draft, and publishes it once every asset
  and `latest.json` are in place.
- After publishing:
  - `desktop-latest/latest.json` names 0.24.0 with links under
    `releases/download/v0.24.0/`, and a desktop app on 0.23.0 offers the
    update.
  - An Android app on 0.23.0 offers 0.24.0.
  - `curl -fsSL https://offdesk.dev/install | sh` installs 0.24.0, and
    `offdesk version` reports it; `offdesk machines` shows nodes behind until
    they update.
  - With an updated Hub and node, a Claude Code started in a new folder shows
    the trust approval in `offdesk runs --waiting`, and `offdesk answer --approve`
    gets it past.
  - The iOS build reached TestFlight; offer it to testers with `TestFlight
    Release Distribution`, `release_tag` `v0.24.0`.
- Publish the same Web UI to the `stable` channel.
