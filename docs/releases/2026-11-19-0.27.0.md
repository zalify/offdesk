# 0.27.0: Talk to your agents from Offdesk

Release scope: everything ships in the one release `v0.27.0`, upgrading from
0.26.0:

- the Hub, node and CLI;
- the desktop app for macOS, Windows and Linux;
- the Android app;
- iOS, through TestFlight.

Reading conversations and continuing local sessions needs the new Hub **and**
the new node. Upgrade the Hub first.

## Changes

- **Read an agent run's conversation and send it messages, also over a bridge**
  (#650, OFF-143).
  - The node reads the conversation from the agent's own session file (Claude
    Code's or Codex's): what was said, and each tool call in one line. It never
    reads terminal output, tool output or thinking, and the hub doesn't keep it.
    Node capability: `agent-transcript-v1`.
  - `GET /api/agent-runs/{id}/messages` reads it (`after` gets only what's
    new). `POST /api/agent-runs/{id}/message` types a message into the run's
    terminal and presses Enter.
  - Tokens and bridges get a new content level, `conversation`, and the scope
    `runs:message` now does something. Bridges get the `messages` and
    `message` commands (`docs/agent-bridge-protocol.md`).
- **Your own Claude Code and Codex sessions, read and continued in Offdesk**
  (#651, OFF-143).
  - The node lists the recent sessions on its machine that no Offdesk terminal
    runs: ones started in your own terminal, or ones that have ended. Each has
    a title, which is its name or else what you first said, and says whether
    another terminal still has it open. Node capability: `local-sessions-v1`.
  - `GET /api/machines/{id}/sessions` lists them, and
    `.../sessions/{agent}/{id}/messages` reads one. A start with `resume`
    continues one (`claude --resume`, `codex resume`) in a new terminal.
  - Bridges get the `sessions` and `session_messages` commands, and `start`
    takes `resume`.
- **Uploads are queued, send chunks in parallel, and show speed and time left**
  (#649, #647). The parallel uploads need the new node; with an older node,
  chunks are sent one at a time as before.
- **The file list stays in place after file actions** (#648).
- **The agent browser looks like a normal Chrome to bot checks** (#641).
- CI and release fixes (#644, #645, #646; development only).

## Upgrading

- Upgrade the Hub before the nodes.
- A bridge only sees conversations and sessions at the `conversation` content
  level. A bridge's access can't be changed, so pair it again to get this
  (`offdesk bridges rm <name>`, then `add … --content conversation`).
- The interface parts reach installed apps through the Web UI `stable`
  channel.

## Validation and publication

- Run CI on the release preparation, then merge and tag `v0.27.0` on the
  merge commit. The Release workflow checks the tag, builds every component
  into the draft, and publishes the release once every asset and
  `latest.json` are in place.
- Check that `updater-channel` and `mirror` uploaded rather than skipped.
- After publishing:
  - Check that `https://offdesk.dev/updates/desktop/latest.json` and GitHub's
    `desktop-latest/latest.json` name 0.27.0.
  - With a token at the `conversation` level,
    `GET /api/agent-runs/{id}/messages` returns a running Claude Code agent's
    conversation, and `GET /api/machines/{id}/sessions` lists that machine's
    recent sessions.
  - Offer the iOS build to testers with `TestFlight Release Distribution`
    (`release_tag` `v0.27.0`), and publish the Web UI to `stable`.
