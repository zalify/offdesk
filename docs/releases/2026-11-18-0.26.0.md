# 0.26.0: A Finder-style file manager

Release scope: everything ships in the one release `v0.26.0`, upgrading from
0.25.16:

- the Hub, node and CLI;
- the desktop app for macOS, Windows and Linux;
- the Android app;
- iOS, through TestFlight.

The file manager needs the new Hub **and** the new node. Upgrade the Hub first.

## Changes

- **Manage files on a machine, not just view them** (#642). The file browser
  becomes a Finder-style file manager. Design:
  `docs/plans/2026-11-17-finder-file-manager.md`.
  - **Desktop.** The overlay grows to 1400×900. It gains:
    - a sidebar (Home, the open terminals' folders, pinned folders);
    - back/forward and a typed path (⌘L / ⌘⇧G);
    - a sortable list view, and an icon view with thumbnails;
    - multi-select and a status bar;
    - a context menu: new folder/file, rename (F2), duplicate, copy/cut/paste,
      move to trash, download (folders and multi-selections as a zip), copy
      path, open in terminal, pin;
    - drag and drop to upload and to move (⌥ copies), with a progress strip;
    - Keep Both / Replace / Stop when a name is taken.
  - **Desktop rows now select on click and open on double-click or Enter.**
  - **Phone.** Long-press selects, and an action bar acts on the selection. A
    paste bar drops moved or copied items into the folder you navigate to. A
    "+" sheet creates a folder or file, or uploads one; a Places sheet lists
    where to go.
  - **Delete moves items to the machine's trash** (freedesktop trash on Linux,
    `NSFileManager` on macOS). It never deletes permanently.
  - Limits:
    - downloads up to 256 MB;
    - zips up to 1 GB of input and 256 MB of output;
    - uploads need the file's size plus 16 MB free.
  - Protocol: the node capability `fs-ops-v1`, and new Hub routes under
    `/api/machines/{id}/fs/`: `op`, `upload/*`, `read_range` and `zip`.
    - An older node answers "Update this machine to manage files".
    - An older Hub answers "Update the hub to manage files".
- **Terminals come back after a reboot on macOS** (#640). macOS nodes never
  recorded a boot id or the agent's command line, so they dropped every
  terminal after a restart, and agents could not be resumed. Both now work, from
  the first restart after updating the node.
- **Phone: recent sessions and machine load** (#638, OFF-142).
  - The sessions sheet can list sessions by latest output.
  - The header shows cpu, memory and disk load, and Machines has a readout for
    each machine.
  - The title bar is back to two lines.
- **Renaming a tab keeps what you type** (#637, OFF-138). The input no longer
  snaps back to the old name while the terminal behind it updates.
- E2E images cache Cargo builds between runs (#639; development only).

## Upgrading

- Upgrade the Hub before the nodes.
- The interface parts reach installed apps through the Web UI `stable`
  channel. The file actions and the macOS reboot fix need the new node on each
  machine.

## Validation and publication

- Run CI on the release preparation, then merge and tag `v0.26.0` on the
  merge commit. The Release workflow:
  - checks the tag against both version numbers;
  - builds every component into the draft;
  - publishes the release once every asset and `latest.json` are in place.
- Check that `updater-channel` and `mirror` uploaded rather than skipped.
- After publishing:
  - Check that `https://offdesk.dev/updates/desktop/latest.json` and GitHub's
    `desktop-latest/latest.json` name 0.26.0.
  - On a macOS node, move a file to the trash from the file manager. It
    appears in the Finder Trash, and no automation prompt appears.
  - On the phone app, "+" → Upload opens the system picker, and long-press
    selects a row.
  - Offer the iOS build to testers with `TestFlight Release Distribution`
    (`release_tag` `v0.26.0`), and publish the Web UI to `stable`.
