# 0.25.6 — Edit text files, and a pinned sessions list

Release scope: everything, in the one release `v0.25.6`: the Hub, node and CLI,
the desktop app for macOS, Windows and Linux, the Android app, and iOS through
TestFlight, all from 0.25.5. Both features need the new Hub and node: file
editing needs both to save, and the sessions list needs them to show how long
ago each terminal had output.

## Changes

- **Edit text files from the file browser** (#600, OFF-81). A text file's
  preview has an **edit** button that opens a plain editor with **cancel** and
  **save** (Esc and ⌘/Ctrl+S on desktop), on desktop, phone and tablet.
  - A save never overwrites a newer change: the node checks the file still
    matches what was read (SHA-256) and otherwise refuses, and the editor
    offers to reload.
  - The node writes atomically and keeps the file's permissions (a `0600`
    `.env` stays `0600`). Only existing UTF-8 text files can be edited; line
    endings and a BOM are kept.
  - Unsaved changes keep the browser open until saved or cancelled.
  - Writing is limited to the machine's owner; scoped API tokens can't, and the
    button is hidden under the view-only lock. With an older Hub or node the
    button doesn't appear.
- **Pinned sessions list on desktop** (#599, OFF-82). On windows 1024px and
  wider, `≡` shows or hides a 300px sessions sidebar pinned beside the panes,
  shown by default. It lists terminals latest output first (`recent`, with
  ages like `5m`), or as the tab tree (`tabs`). Narrower windows keep the
  drawer, and phones and tablets are unchanged. The node reports each
  terminal's last output from tmux, at most every 30 seconds; terminals on
  older nodes show no age.
- **E2E:** the keyboard refit test no longer races its own frame sampler
  (#601).

## Validation and publication

- Run CI on the release preparation, then merge and tag `v0.25.6` on the merge
  commit. The Release workflow checks the tag against both versions, builds
  every component into the draft, and publishes it once every asset and
  `latest.json` are in place.
- Check that `updater-channel` and `mirror` uploaded, not skipped.
- After publishing:
  - `https://offdesk.dev/updates/desktop/latest.json` and GitHub's
    `desktop-latest/latest.json` name 0.25.6, and a desktop app on 0.25.5
    offers the update.
  - `curl -fsSL https://offdesk.dev/install | sh` installs 0.25.6.
  - With the Hub and a node on 0.25.6, open a text file in the file browser,
    edit and save it, and check it on the machine.
  - On a desktop window, the sessions sidebar shows terminals with ages, latest
    output first.
  - Offer the iOS build to testers with `TestFlight Release Distribution`,
    `release_tag` `v0.25.6`.
- Publish the same Web UI to the `stable` channel.
