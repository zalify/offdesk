# 0.25.11 — Agent sessions say what they're about

Release scope: everything, in the one release `v0.25.11`: the Hub, node and CLI,
the desktop app for macOS, Windows and Linux, the Android app, and iOS through
TestFlight, all from 0.25.10. The run titles and Getting started are in the Hub
and the node; the unreachable-Hub screen is in the interface.

## Changes

- **Agent runs are named after their session's title** (#619, OFF-112). Only
  runs the Hub starts have a label, so a Claude Code session someone started by
  hand in a terminal could only be shown by its folder. Since 0.25.10 recognises
  Claude Code's native build, every such session showed up that way, and runs
  that split before 0.25.10 lost their task's name too.
  - An open run carries `title`: its terminal's title as the agent set it
    (Claude Code names the conversation there), without the mark in front
    (✳, spinners). A shell's own title (`user@host:path`), a path, or the
    agent's bare name gives none.
  - A new name re-announces the run and is a `run.title` event for webhooks and
    bridges. The title is `notes` content: below that level it's left out.
- **Getting started progress, and looking for agents again** (#616, OFF-7). The
  Hub side of onboarding: `GET` / `PATCH /api/onboarding` reports which steps
  are done from the Hub's real state (a paired device, a terminal started, a
  second machine, a remote address) and stores only what was dismissed.
  `POST /api/machines/{id}/agents/refresh` asks a node to look for coding agents
  again, so an agent installed after the node connected shows up. No UI yet.
- **A desktop client that can't reach its Hub says so** (#618). After 10 seconds
  it shows the address it can't reach and keeps retrying, so it picks up by
  itself when the Hub returns. **Connect to a different Hub** drops the login
  and goes to sign-in (hidden for encrypted pairings).

## Upgrading

- Run titles need the new Hub; the node is unchanged for them. Clients that
  don't know `title` ignore it. After the update the Hub's snapshot to bridges
  carries the titles of open runs, and later renames arrive as `run.title`.
- The Hub adds a `title` column to `webhook_run_state` and an
  `onboarding_marks` table on start. Nothing is removed.
- Agents refreshing on request needs the new node; an older node ignores the
  message.
- A Claude Code session started by hand still reports its state only if
  Offdesk's hooks are installed (`offdesk agents hooks install`, then restart
  the session). Without them its status stays at what the node saw.

## Validation and publication

- Run CI on the release preparation, then merge and tag `v0.25.11` on the merge
  commit. The Release workflow checks the tag against both versions, builds
  every component into the draft, and publishes it once every asset and
  `latest.json` are in place.
- Check that `updater-channel` and `mirror` uploaded, not skipped.
- After publishing:
  - `https://offdesk.dev/updates/desktop/latest.json` and GitHub's
    `desktop-latest/latest.json` name 0.25.11, and a desktop app on 0.25.10
    offers the update.
  - `curl -fsSL https://offdesk.dev/install | sh` installs 0.25.11.
  - With Claude Code started by hand in an Offdesk terminal, `GET
    /api/agent-runs` shows its run with a `title` once the conversation has a
    name, and a bridge at `notes` level gets a `run.title` event when it
    changes.
  - Offer the iOS build to testers with `TestFlight Release Distribution`,
    `release_tag` `v0.25.11`.
