# iOS 0.9.2 — interface updates without TestFlight

Release scope: iOS through TestFlight (`ios-v0.9.2`). Nothing else changes.

## Changes

- The app carries the Web UI release key, so interface changes reach the
  iPhone and iPad app like the other apps, without a new TestFlight build
  (#536). 0.9.1 was meant to, but `cargo tauri ios build` runs cargo from an
  Xcode build phase that does not see the workflow's environment, so it was
  built without the key. The workflow now writes the key into cargo's own
  config, and refuses to upload an IPA whose app does not contain it.

## Validation and publication

- Run CI on the release preparation, then merge and tag `ios-v0.9.2` on the
  merge commit. The build fails before the TestFlight upload if the key is
  missing.
- Install the TestFlight build and check Settings › About shows the interface
  version and the `stable` channel. The next stable Web UI should then reach
  it after a relaunch.
- Publish the iOS release without moving GitHub's global Latest off the Hub
  release.
