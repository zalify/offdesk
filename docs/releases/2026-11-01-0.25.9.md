# 0.25.9 — Agents know their session, and onboarding in the workspace frame

Release scope: everything, in the one release `v0.25.9`: the Hub, node and CLI,
the desktop app for macOS, Windows and Linux, the Android app, and iOS through
TestFlight, all from 0.25.8. Both changes touch more than the interface, so
they need this release.

## Changes

- **Every terminal tells its agents their session** (#613). Each terminal's
  shell starts with `OFFDESK_SESSION` set to the terminal id, so an agent
  started by hand has it too. Offdesk Cloud can put an agent's task on the
  session it runs in. Terminals already open don't have the variable until
  they are opened again.
- **Onboarding runs in the workspace frame** (#612, #614). First run, hub setup
  and hub ready share one frame, with the steps where the tab bar goes and live
  state on the status line. A port that's taken is caught before install, which
  names what holds it and moves the hub to the next free port, and the hub's
  commands follow that port. A tmux failure offers its repair, the pairing code
  appears unasked and replaces itself when it expires, and the screen turns to
  the phone when a new device pairs.

## Validation and publication

- Run CI on the release preparation, then merge and tag `v0.25.9` on the merge
  commit. The Release workflow checks the tag against both versions, builds
  every component into the draft, and publishes it once every asset and
  `latest.json` are in place.
- Check that `updater-channel` and `mirror` uploaded, not skipped.
- After publishing:
  - `https://offdesk.dev/updates/desktop/latest.json` and GitHub's
    `desktop-latest/latest.json` name 0.25.9, and a desktop app on 0.25.8
    offers the update.
  - `curl -fsSL https://offdesk.dev/install | sh` installs 0.25.9.
  - In a new terminal, `echo $OFFDESK_SESSION` prints the terminal's id, and
    terminals open from before the update still work.
  - On a fresh install, onboarding reaches hub ready, and with something else
    on port 4317 it moves the hub to the next free port.
  - Offer the iOS build to testers with `TestFlight Release Distribution`,
    `release_tag` `v0.25.9`.
- Publish the same Web UI to the `stable` channel.
